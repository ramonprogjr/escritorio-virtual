**Visão de marketplace do dono (29/jun).** Docs: `servicos-cadeia-contratacao-monetizacao.md` + `ifood-construcao-pedidos.md`.

**Cadeia de serviços (ofícios):** módulo Serviços (em Engenharia) com marcenaria, marmoraria, vidraçaria, serralheria, pintura, elétrica, etc. **Hierarquia de contratação:** arquiteto → engenharias/empreiteiras → prestadoras de serviços → **mão de obra cadastrada** (sob demanda; = especialistas sem login). Cada elo = transação via Hub → **capitaliza em cada camada** (spread/split por código único). Razão: **mão de obra é commodity raro e caro** → controlar a cadeia = valor defensável.

**"iFood da construção":** venda de produtos/materiais/eletros/ferramentas + **aluguel de equipamentos**; **PEDIDOS compartilhado por todos**. Dor: stockout → mão de obra parada. 

**Minha avaliação (CEO, honesta — o dono pediu):** diferencial REAL, mas o ouro NÃO é "entregar rápido" — é **preditivo** (o sistema sabe a necessidade antes, porque tem o cérebro da obra: EAP+cronograma+estoque E5+bloqueio E3). Esse é o fosso. Construir **asset-light** (Obra10 ORQUESTRA, não estoca/frota; fornecedores da rede cumprem; Obra10 = trilho+demanda+spread+escrow), **regional primeiro**, **em fases** (E5=fundação agora → marketplace asset-light fase 2 → logística fase 3).
