**A ALMA DO PRODUTO (dono, 29/jun):** o sistema existe para **retirar dores REAIS** do cliente final da obra. O cliente tem **usuário próprio** — visão **dashboard-first + analytics, curada e honesta** (NÃO a interface pesada de obra do gestor): ver **avanço, relatórios, financeiro, cronograma**; **acompanhar** (diário de obra + fotos/vídeos = visão realista) e **aprovar**. A ligação arquiteto↔obra passa **SEMPRE pelo Hub** (ponto de auditoria e controle).

**Os 5 MEDOS → a tela mostra a CURA + segurança** (regra de design: cada elemento mapeia um medo→cura):
1. atrasar → cronograma honesto previsto×realizado + Curva S + alerta sem esconder.
2. não acabar a obra → avanço físico real + saúde + marcos.
3. não saber o que acontece → diário + fotos/vídeos + "o que aconteceu esta semana".
4. ser enganado → **selo de auditoria do Hub** (cada número verificado), transparência.
5. perder dinheiro → financeiro claro (pago×a pagar×saldo), gate humano no dinheiro.

**Honesto e justo, sem mentiras, com controle** — a honestidade É o diferencial de confiança. Por isso o **módulo Arq+Eng do Hub** terá processo **rigoroso de auditoria/conduta/qualidade/segurança**, com lastro do time real do dono: **engenheiros, arquitetos, engenheiros de segurança, advogados, contadores**.
